01 — The Problem

把一场会议录音变成公众号文章，要听写、跨工具查上下文、写初稿、调腔调、查重 — 一个人来回切 5 个工具，半天没了。

02 — Our Solution

comp-voice 把录音、enterprise-search、Slack 搜索、公众号语料、internal-comms 串成一条流水线，最后输出可直接粘进公众号编辑器的 markdown 草稿，并把所有中间证据落盘交给第三方 LLM 做裁判。

03 — Capabilities

Made for 需要把内部技术讨论写成对外公众号的研发负责人 / 技术品牌团队 / 独立开发者 on a deadline.

Every part is designed to feel intentional, opinionated, and useful from the first run.

05 — Install

Two lines, your machine.

MIT licensed. Self-hosted. Vendored fallbacks for every upstream plugin — works even without enterprise-search / slack / talk-html installed.

# 1. Clone & register the plugin into your Claude Code config
git clone https://github.com/LiuShiyuMath/comp-voice ~/projects/comp-voice
# point your ~/.claude/plugins/ at it (see CONNECTORS.md)

# 2. Run on a real recording
/comp-voice:compose-mp ~/Recordings/meeting.m4a --preview-html --emit-judge

# Output lands in .judge/mp-<timestamp>/ — same shape as examples/golden-run/

07 — Frequently asked

Common questions.

我的录音会不会被上传到云?
不会. Transcription 走本地 whisper-family 模型, 音频文件留在你机器上. comp-voice 自己不发任何外网请求 — 只有你已经装的 Claude Code、enterprise-search、Slack 这些 plugin 会按它们各自的策略走网络.
如果我没装 enterprise-search / slack / talk-html 怎么办?
能跑. 仓库里 vendored 了这四个 skill 的最小回退版本 (见 skills/vendored-*). 真有的就用真的, 没有就用回退 — 不会因为缺一个 upstream 就直接挂掉. 见 CONNECTORS.md.
飞书呢? 我们公司用的是飞书不是 Notion / Slack.
v0.1 不接飞书 OAuth — 那是一周工作量但只省一次粘贴. 当前做法: 直接把飞书文档内容贴进 prompt, 或者 export 成 md 喂给 enterprise-search 的 file source. Feishu MCP 等官方/社区版本出来再原生接入.
judge.json 到底在评什么? 谁来打分?
compose-mp 不给自己打分, 只 dump 一份机器可读记录: pipeline 8 步是否都跑完、draft 字数/结构/合规清单、跨源 grounding 映射 (每条数据来自 transcript 哪一秒 + slack/notion 哪条). 然后由一只独立 LLM (haiku / 另一个 sonnet session) 只读 raw JSON + evidence 当裁判. 看真实样例: examples/golden-run/judge.json.
v0.1 没做的 (但有人会问)?
飞书 OAuth、公众号 publishing API、自动配图生成、Web UI、SaaS hosting. 都试过想清楚, 都没上 — 当前阶段把核心 evidence pipeline 做厚比堆 feature 重要. Roadmap 在 README 里, 不藏.

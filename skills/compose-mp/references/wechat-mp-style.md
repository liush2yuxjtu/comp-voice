# 微信公众号 voice & structure reference

This file encodes 公众号 idioms that `/marketing:draft-content` does not natively know about. Load when drafting in step 6 of `compose-mp`.

## 平台特性

- **阅读环境**: 手机竖屏, 单手滑动, 灯光弱, 注意力碎片化。每段建议 ≤ 4 行手机屏宽 (~80字)。
- **入口**: 朋友圈 / 群分享 / 订阅推送。**前 100 字是生死线** —— 朋友圈预览只露这一截。
- **阅读完成率**: 行业平均 30-40%。设计上要让人滑到 50% 处仍想继续。
- **打开率红线**: 标题决定一切。15字内, 信息量 + 钩子, 不要标题党但要"开窗口"。

## 标题模板 (12-22字)

- **冲突型**: "我们以为 X, 结果发现 Y" / "为什么 ____ 反而 ____"
- **数字型**: "30 天后, 这个团队____" / "3 个让我后悔____的决定"
- **悬疑型**: "如果你不知道 X, 这篇值得读一次"
- **第一人称**: "做 X 三年, 我学到的最反直觉的一件事"
- **避免**: 纯说教标题, 多于一个标点符号, 全是问号

给用户 2-3 个候选标题。

## 段落结构 (强约束)

```
引言 (100-300字)
  └─ 钩子句 (1-2句, 制造痛点 / 提出反问 / 抛出意外事实)
  └─ 立场预告 (1句, 暗示文章会推翻什么共识)

正文 §1, §2, §3 (各 300-600字, 通常 2-3 节)
  └─ 小标题 (8-15字, 句子型不要名词型)
  └─ 一个论点 + 一个具体例子 + 一句总结
  └─ 段落之间用空行, 不要长块状

结语 (100-200字)
  └─ 收束论点
  └─ 一个动作号召 OR 一个反思问句
  └─ 留白, 不要"以上就是今天的分享"这种废话
```

## 句式与节奏

- **短句优先**。一句话 ≤ 25 字最好。需要长句时, 用句号/破折号断开。
- **避免书面语**: "进行" "实施" "诸如" "由此可见" → "做" "搞" "比如" "所以"。
- **避免英文夹杂**: 必要时英文术语在第一次出现时给中文释义, 之后用中文。例外: 不可译的产品名 (Slack, Notion)。
- **少用感叹号**。整篇全文 ≤ 2 个。
- **疑问句作节奏点**: 每节末尾一个反问句, 推动读者继续往下滑。

## 视觉节奏

- **emoji**: 标题不放; 正文每节最多 1 个, 用于强调而非装饰; 结语不放。
- **加粗**: 一篇全文 ≤ 5 处, 只加粗"金句" (用户截图传播的句子)。
- **引用块** (`>`): 一篇 ≤ 2 个, 用于关键的反直觉断言。
- **分隔线** (`---`): 仅在正文与结语之间, 或正文与配图建议之间。

## 配图建议槽位

公众号编辑器需要至少 1 张封面图 (16:9) + 每个正文节 1 张配图。在 draft 末尾给图片 prompt 描述, 用户可以拿去喂图生模型:

```markdown
**配图建议**
- 封面 (16:9): 一个 ____ 正在 ____, 极简插画风, 主色 #1E40AF / #F59E0B, 不要文字
- §1 (4:3): ____
- §2 (4:3): ____
```

每个 prompt:
- 包含场景 + 主体 + 风格 + 配色
- 明确写"不要文字" (中文图生模型会瞎加水印)
- 16:9 或 4:3, 不用 1:1 (公众号不推荐方图)

## 长度甜区

- **快讯 / 短评**: 800-1500 字 — 适合突发事件、行业动态
- **主流 long-form**: 2000-3500 字 — 适合观点、方法论、复盘 ← **默认**
- **深度万字**: 5000-8000 字 — 适合年终总结、白皮书改编, 公众号会自动折叠"阅读全文"

未指定 → 默认 2500 字。

## 不要做的事

- 不要"在 ____ 上, 我们看到了 ____" 这类 LinkedIn 翻译腔
- 不要在结语写"欢迎留言转发点赞" —— 假, 显得急迫
- 不要给文章加"前言 / 一、二、三 / 总结" 这种公文骨架
- 不要让正文超过 3 个 §, 公众号不是论文
- 不要每段都拿数据砸人 —— 一个具体场景 + 一个数据比五个数据有效
- 不要混入"AI生成"的标志性废话: "在这个快速变化的时代", "让我们深入探讨", "毫无疑问"

## 复用既有题目的判断

draft 之前对比 `mp-corpus.md` 里近 30 天的题目。如果发现:
- **同一主题, 不同角度** → 在引言显式说 "上篇 ____ 之后, 这次想从 ____ 来看"
- **同一主题, 同一角度** → 停下来问用户: "和 ____ 这篇撞了, 是要改 angle 还是合并?"
- **不重叠** → 正常往下

## 输出 checklist (写完后自检, 不写入 draft, 写入 judge.json)

- [ ] 标题 12-22 字
- [ ] 前 100 字含钩子
- [ ] 3 节正文 (或 2 节, 但不要 ≥4 节)
- [ ] 总字数在 2000-3500 之间 (除非用户指定)
- [ ] 至少 4 个图片 prompt (1 封面 + 3 内文)
- [ ] 全文感叹号 ≤ 2
- [ ] 没有 "在 ____ 上" / "深入探讨" / "毫无疑问" 等 AI 废话
- [ ] 没有重复 mp-corpus 已发题目
